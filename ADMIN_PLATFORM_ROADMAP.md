# ArcVPN Business Console — план развития

Обновлено: 2026-08-13.

## Что считаем источником правды

- Remnawave: пользователи, ноды, фактический online и трафик.
- ArcVPN DB: оплаты, подписки, устройства, рефералы, обращения поддержки.
- Node Agent: CPU/RAM/disk/network, сервисы, логи и глубокие проверки.
- Client-side Happ profile: автовыбор и LTE fallback. Сервер видит фактическую
  RemnaNode, но не может достоверно узнать, что пользователь нажал профиль
  «Автовыбор».

## Этап 1 — операционный центр

- [x] RemnaNode health, online, ресурсы, трафик и активные inbound.
- [x] Фактическое распределение online-пользователей по нодам.
- [x] Карточка клиентского автовыбора и две LTE CDN-доставки.
- [x] Ручная глубокая проверка портов.
- [ ] История latency/loss/jitter/throughput по каждой ноде за 1ч/24ч/7д.
- [ ] Полная проверка через реальный тестовый VLESS/Hysteria-клиент.
- [ ] Внешние probes минимум из двух независимых сетей.
- [ ] Карта инцидента: DNS → CDN → origin → Xray → внешний сайт.

## Этап 2 — управление инфраструктурой

- [ ] Node Agent с исходящим mTLS-соединением и очередью команд.
- [ ] Управление systemd-сервисами, UFW, сертификатами и логами без SSH.
- [ ] Версионирование конфигов, dry-run, проверка и быстрый rollback.
- [ ] Визуальные схемы маршрутов: client → CDN/direct → inbound → outbound.
- [ ] Автосинхронизация GeoAssets с проверкой checksum и откатом.
- [ ] Профили производительности: safe/recommended/aggressive.
- [ ] Автоматизация CDN, DNS и сертификатов через API провайдера.

- [ ] Детектор шаринга, перепродажи, port scan, botnet/mining/proxyware.

- [ ] Роли владельца/оператора/поддержки и обязательная 2FA.
- [ ] Зашифрованные ежедневные backup БД/Remnawave/config в удалённое хранилище.
- [ ] Проверяемое восстановление из backup раз в месяц.
- [ ] Telegram alerts с дедупликацией, severity и ссылкой на инцидент.

## Email без SaaS

Рекомендуем отдельную маленькую VPS, а не VPN-ноду и не сервер панели.

1. Получить VPS с чистым выделенным IPv4, открытым портом 25 и возможностью
   установить PTR `mail.arccnet.space`.
2. DNS: `A mail`, `MX @ mail.arccnet.space`, затем SPF, DKIM и DMARC.
3. Установить Mailcow (предпочтительно 4 ГБ RAM) либо docker-mailserver
   (экономнее, но больше ручного обслуживания).
4. Создать `support@arccnet.space`, `noreply@arccnet.space`, отдельный SMTP
   credential для приложения и лимиты отправки.
5. Включить TLS, fail2ban, backup почты, мониторинг очереди и blacklist IP.
6. Сначала DMARC `p=none`, после проверки доставки перейти на `quarantine`,
   затем `reject`.

Самостоятельная почта даёт контроль, но не гарантирует доставляемость кодов:
репутация нового IP прогревается постепенно.
