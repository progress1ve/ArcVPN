# ArcVPN: план полноценного продукта

Обновлено: 30 июля 2026.

Этот документ — единый рабочий план для WebApp, пользовательского интерфейса
Telegram-бота, подписок, платежей и эксплуатации. После каждого этапа здесь
отмечается фактически завершённая работа.

## 1. Продуктовая модель трафика

### Рассматриваемая модель: единый взвешенный пакет

- Пользователь видит один месячный пакет.
- Обычные подключения расходуют `1 ГБ` за `1 ГБ`.
- Inbound «Обход глушилок (LTE)» расходует `10 ГБ` пакета за `1 ГБ`.
- Предлагаемый стартовый пакет: `500 ГБ` взвешенного трафика в месяц.
- Включённые `20 ГБ` реального LTE-трафика эквивалентны `200 ГБ` общего пакета.
- Дополнительные `5 ГБ LTE` эквивалентны `50 ГБ` общего пакета и стоят `10 ₽`
  за месяц тарифа.

### Важное ограничение

3x-ui сейчас отдаёт агрегированный клиентский трафик, а не достоверную разбивку
по inbound. Для множителя `×10` нужен собственный счётчик трафика:

1. получать usage отдельно для обычных и LTE-inbound;
2. хранить сырые байты и контрольную точку счётчика;
3. рассчитывать `обычный + LTE × 10`;
4. защищаться от обнуления/перезапуска Xray и отрицательных дельт;
5. синхронизировать рассчитанный остаток с панелью и WebApp.

До завершения такого счётчика действующие лимиты пользователей не уменьшаются.
В интерфейсе множитель должен быть написан явно до покупки, иначе единый пакет
будет восприниматься как скрытое списание.

### Утверждённое решение

- [x] Владелец выбрал модель `500 ГБ, LTE ×10`.
- [x] Миграция v31 добавляет сырой обычный usage, месячный лимит и границы цикла.
- [ ] Подключить отдельный источник normal/LTE usage и только после проверки
  включить новый лимит вместо действующих 1024 ГБ.

В интерфейсе до покупки и на главной странице будет явно написано:
`500 ГБ в месяц · обход глушилок расходует трафик ×10`.

## 2. WebApp — обязательный production scope

### 2.1. Подписка и платежи

- [x] Тарифная карусель, СБП, базовые тарифы и возврат из банка.
- [x] Desktop-стрелки тарифной карусели.
- [ ] YooKassa webhook: оплата применяется без возврата пользователя в WebApp.
- [ ] Периодическая сверка зависших платежей.
- [ ] Идемпотентное применение платежа и защита от двойного продления.
- [ ] Страницы: ожидание, успешно, отменено, ошибка, ручная проверка.
- [ ] Электронные чеки и настоящие реквизиты продавца.
- [ ] Хранение и применение купленных устройств и LTE-пакетов.

### 2.2. Устройства

- [x] Регистрация импорта по анонимному стабильному device token.
- [x] Первые разрешённые устройства получают профиль, лишние — информационный.
- [x] Постоянные поля `device_limit`, `lte_quota_gb`, `lte_used_bytes` и поля
  запрошенных add-ons платежа добавлены миграцией v30; API устройств возвращает
  актуальные entitlement-значения.
- [ ] Применение купленных значений после подтверждённой оплаты.
- [ ] Отдельная device-bound ссылка подписки для каждого слота.
- [ ] Миграция старых общих ссылок без внезапной блокировки пользователей.
- [ ] Переименование, отключение, замена и освобождение слота.
- [ ] Состояния: импортировано, активно, последнее подключение.
- [ ] Уведомление «Новое устройство» с действием «Это не я».
- [ ] Сбор модели устройства только при наличии данных от VPN-клиента. Happ
  может не передавать точную модель; WebApp не должен её выдумывать.

### 2.3. Трафик и срок

- [ ] Точный обычный usage.
- [ ] Точный LTE usage по inbound.
- [ ] Ежемесячный reset с журналом и защитой от повторного выполнения.
- [ ] Уведомления на 80%, 95% и 100%.
- [ ] История расхода по дням без хранения сайтов пользователя.
- [ ] Корректные состояния истёкшей, исчерпанной и резервной подписки.

### 2.4. Аккаунт и поддержка

- [x] Telegram-вход и привязка email в UI.
- [x] Чат с менеджером и ответы через бота.
- [ ] Настоящий SMTP и восстановление входа по email.
- [ ] Управление активными web-сессиями.
- [ ] Вложения в поддержку: скриншот и диагностический отчёт без секретов.
- [ ] Категории обращений, статус и уведомление об ответе.
- [ ] Реальные реквизиты, соглашение и политика обработки данных.

### 2.5. Качество

- [ ] Skeleton/error/offline состояния всех экранов.
- [ ] Защита API: rate limit, audit событий, проверка сессий и CSRF там, где нужен.
- [ ] Клиентский журнал ошибок без токенов, URL подписок и переписки.
- [ ] Аналитика воронки: trial → импорт → подключение → покупка → продление.
- [ ] E2E на iOS, Android, Windows, Telegram Desktop и обычном браузере.
- [ ] Accessibility: клавиатура, focus, contrast, reduced motion.

## 3. Telegram-бот — новый пользовательский UI

Админка остаётся существующей. Полностью меняется только пользовательская часть.

### 3.1. Единая дизайн-система

- Новый логотип ArcVPN во всех сообщениях и аватарке поддержки.
- Цвета, скругления, иконки и тон текста совпадают с WebApp.
- Кнопки называются одинаково в боте и WebApp.
- Одна главная CTA на экран; резервные действия визуально вторичны.
- Старые разрозненные emoji и технические формулировки удаляются.

### 3.2. Новый пользователь

1. Проверка обязательной подписки на канал.
2. Автоматическое создание trial без отдельной кнопки получения.
3. Фирменная картинка-приветствие.
4. Короткое сообщение «Пробный доступ активирован».
5. Кнопка `Подключиться` открывает fullscreen WebApp direct link.
6. Кнопка `Продолжить в боте` открывает резервное пользовательское меню.

### 3.3. Резервное меню бота

- Главная: срок, устройства, трафик, статус.
- Подключение: ссылка/QR, устройство и краткая инструкция.
- Продление: те же тарифы и СБП, что в WebApp.
- Друзья: ссылка и правило `+15 дней обоим после покупки`.
- Поддержка: FAQ и создание обращения.
- Настройки: уведомления, устройства, email, соглашение.
- Кнопка `Открыть WebApp` остаётся основной на каждом ключевом экране.

### 3.4. Транзакционные сообщения

Новый единый стиль нужен для:

- trial активирован;
- устройство подключено;
- оплата создана / получена / не завершена;
- осталось 3 дня / 1 день / подписка закончилась;
- трафик 80% / 95% / закончился;
- превышен лимит устройств;
- реферальный бонус начислен;
- ответ поддержки;
- технические работы и восстановление сервиса.

Каждое сообщение содержит одно понятное действие и не раскрывает UUID, токены,
внутренние адреса или названия серверных компонентов.

### 3.5. Графика

Нужен согласованный набор иллюстраций без текста внутри изображения:

- welcome/trial;
- подключение устройства;
- успешная оплата;
- подписка заканчивается;
- приглашение друга;
- поддержка;
- технические работы;
- успех/восстановление.

Рабочий формат: WebP, `1280×720` для широких сообщений и `1080×1080` для
универсальных карточек, прозрачный фон только для отдельных объектов. Перед
генерацией фиксируются один свет, материалы, угол камеры и палитра ArcVPN.
