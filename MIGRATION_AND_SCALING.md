# Переезд сервиса и добавление серверов

Краткая практическая инструкция. Два разных сценария:
- **Часть A** — перенести сам сервис (бот + API подписок) на другой VPS.
- **Часть B** — добавить ещё один VPN-сервер (ноду 3X-UI), через который подключаются пользователи.

Архитектура (контекст):
- Код: `/root/ArcVPN`. Точка входа бота — `main.py`, API подписок — `subscription_api.py`.
- Сервисы systemd: `arcvpn-bot.service` (бот), `arcvpn-subscription.service` (Flask API на `127.0.0.1:8080`).
- nginx проксирует `:2053 → 127.0.0.1:8080` (TLS), домен задан в `config.py` → `SUBSCRIPTION_URL`.
- БД: `database/vpn_bot.db` (SQLite) — пользователи, ключи, платежи. **В `.gitignore`.**
- `config.py` — токены/секреты. **В `.gitignore`.**
- VPN-ноды = панели 3X-UI, перечислены в таблице `servers` (управляются через админку бота).

## Часть A. Перенос сервиса на новый VPS

> ⚠️ **Самое важное:** `SUBSCRIPTION_URL` (домен) зашит в ссылку-подписку каждого пользователя.
> Если домен поменяется — **все существующие подписки в приложениях перестанут обновляться.**
> Правильный переезд = **сохранить тот же домен**, просто перенаправить его DNS на новый IP.

1. **Новый VPS** (Ubuntu/Debian). Установить пакеты:
   ```bash
   apt update && apt install -y python3 python3-pip git nginx certbot python3-certbot-nginx
   ```
2. **Код:**
   ```bash
   cd /root && git clone https://github.com/progress1ve/ArcVPN.git ArcVPN && cd ArcVPN
   ```
3. **Python-зависимости** (нет requirements.txt — ставим вручную основные):
   ```bash
   pip3 install aiogram flask aiohttp "qrcode[pil]" pytz
   ```
   Если при старте чего-то не хватит — поставить по имени из ошибки `ModuleNotFoundError`.
4. **Перенести секреты и данные со старого сервера** (это НЕ в git):
   ```bash
   # выполнять со СТАРОГО сервера, заменив NEW_IP
   scp /root/ArcVPN/config.py            root@NEW_IP:/root/ArcVPN/config.py
   scp /root/ArcVPN/database/vpn_bot.db  root@NEW_IP:/root/ArcVPN/database/vpn_bot.db
   ```
   > Останавливать бота на старом сервере перед копированием БД, чтобы не потерять свежие записи.
5. **systemd-юниты** (есть в репо):
   ```bash
   cp /root/ArcVPN/arcvpn-bot.service /etc/systemd/system/
   cp /root/ArcVPN/arcvpn-subscription.service /etc/systemd/system/
   systemctl daemon-reload
   systemctl enable --now arcvpn-bot.service arcvpn-subscription.service
   ```
6. **nginx + TLS** для `:2053 → 127.0.0.1:8080` (сохранить тот же домен из `SUBSCRIPTION_URL`).
   Получить/перенести сертификат (`certbot`), затем настроить server-блок на порт 2053 с `proxy_pass http://127.0.0.1:8080;`.
7. **Переключить DNS:** A-запись домена → новый IP. Дождаться обновления.
8. **Проверка:**
   ```bash
   systemctl is-active arcvpn-bot.service arcvpn-subscription.service
   curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/health   # 200
   ```
9. **Выключить старый сервер** только после того, как новый отвечает и DNS переключился.

> Если домен всё же меняется — после переезда пользователям нужно **переимпортировать подписку** (новая ссылка из бота: «Мои подписки» → инструкция). Старайся этого избегать.

## Часть B. Добавить ещё один VPN-сервер (ноду)

Это горизонтальное масштабирование — больше точек подключения для пользователей. Сервис-контроллер (бот) остаётся один.

1. **Поднять новый VPS с панелью 3X-UI**, создать inbound **VLESS Reality** (как на текущих нодах). Записать:
   - host (IP/домен), port панели, `web_base_path` (секретный путь), login, password.
2. **Добавить в боте:** Админка → **Серверы → Добавить сервер** → ввести данные по шагам → дождаться теста подключения → сохранить.
3. **Группы тарифов** (если используешь >1 группы): привязать сервер к нужной группе (Серверы → сервер → «Изменить группу»). При одной группе — ничего делать не нужно.
4. **Готово.** Новые ключи будут выдаваться с учётом активных серверов; в мультисерверной выдаче ключ создаётся на каждом активном сервере.

### Резервный сервер (аварийный Telegram-доступ)
- Помечается в админке: Серверы → сервер → «🟡 Сделать резервным». Бот сам создаёт общий резервный клиент на панели.
- Если серверов **несколько** — резервный исключается из списка покупки (это его роль).
- Если сервер **один** — он остаётся и для покупки, и резервным одновременно (специальный фолбэк в коде).
- Настройки резерва — в `config.py` (`RESERVE_ACCESS_ENABLED`, `RESERVE_DISPLAY_NAME`, домены роутинга). Подробности — в коде `subscription_api.py` и `bot/services/reserve.py`.

## Чеклист «ничего не забыл»
- [ ] `config.py` скопирован (НЕ из git) и `SUBSCRIPTION_URL` корректен.
- [ ] `database/vpn_bot.db` скопирован (НЕ из git), бот на старом сервере был остановлен при копировании.
- [ ] Оба сервиса `active`, `/health` → 200.
- [ ] nginx + TLS на 2053, DNS указывает на правильный IP.
- [ ] Новые серверы добавлены через админку и прошли тест подключения.
- [ ] (Если есть) резервный сервер помечен и `settings.reserve_client` заполнен.

> Напоминание: `config.py` и `database/vpn_bot.db` в `.gitignore` — `git pull` их НЕ обновляет.
> Новые опции конфига в коде читаются через `getattr(config, ..., default)`, чтобы старый `config.py` не ронял сервис.
