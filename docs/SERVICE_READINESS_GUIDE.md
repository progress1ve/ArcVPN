# ArcVPN — что нужно владельцу для полной готовности сервиса

## 1. Платежи YooKassa/СБП

- [x] В кабинете YooKassa проверить боевой магазин и доступность СБП.
- [x] Указать webhook: `https://sub.arccnet.space/api/payments/yookassa/webhook`.
- [x] Включить событие успешного платежа и проверить один реальный платёж каждого
   тарифа: сумма → webhook → активация → сообщение пользователю.
- [ ] Если кабинет потребует чеки, заполнить налоговые параметры и предмет расчёта;
   затем передать их разработчику без публикации секретов в чате или Git.
- [ ] Отдельно проверить возврат и повторный webhook: дни не должны начисляться дважды.

## 2. Email (отложено)

Подготовить почтовый домен и SMTP: host, port, username, password, адрес From.
Настроить SPF, DKIM и DMARC, затем проверить вход и привязку email. Секреты
передавать через `.env` на сервере, не коммитить.

## 3. Юридические данные (отложено)

Подготовить ФИО/наименование владельца, статус, ИНН и адрес при необходимости,
email поддержки и юридический email. Перед публикацией соглашения и политики
обработки данных показать тексты профильному специалисту.

## 4. Telegram

- [x] В BotFather закрепить Main Mini App и режим Fullscreen.
- [x] Menu Button ведёт в WebApp; inline-кнопка использует direct link Mini App.
- [x] Проверить обязательную подписку на канал новым аккаунтом.
- [x] Проверить цепочку: приветствие → trial автоматически → WebApp → импорт Happ.
- [x] Проверить резервный UI бота, если WebApp недоступен.

## 5. Устройства и Happ (отложено)

Уточнить у Happ, передаёт ли приложение устойчивый device ID, модель устройства,
ОС и событие импорта. Без этого точное `iPhone 17 Pro` нельзя гарантировать:
IP-адрес не является устройством. После ответа Happ выбрать интеграцию или
выдавать отдельный токен импорта на каждое устройство.

## 6. Инфраструктура

1. Включить внешний мониторинг из другой сети для сайта, подписки и каждого
   протокола; внутренний guard не заменяет внешний probe.
2. Настроить ежедневный проверенный SQLite backup и недельную копию вне VPS.
3. Раз в месяц проводить тест восстановления на временной машине.
4. Следить за сроками доменов, CDN и TLS-сертификатов минимум за 30 дней.
5. Хранить аварийный доступ у владельца: VPS, DNS, Yandex CDN, GitHub, YooKassa.
6. После стабилизации заменить переданные в чат пароли и перейти на SSH-ключи.
7. Перевести Subscription API со встроенного Flask development server на
   production WSGI (Gunicorn с systemd), затем провести нагрузочный smoke-test.
8. При росте до 800–2000 клиентов держать минимум три data-plane ноды у двух
   независимых провайдеров/ASN и отдельный управляющий сервер без VPN-трафика.
9. Перед годовой оплатой новой ноды проводить 7-дневный canary в вечерние часы;
   фиксировать Mbps, packet loss, jitter, TCP/UDP и работу видео по операторам.
10. Внедрить автоматические состояния `healthy/degraded/draining/offline`, чтобы
    неисправная нода переставала выдаваться новым подключениям без общей аварии.

## 7. Приёмочные тесты перед рекламой

- Новый пользователь, trial, покупка, продление после истечения и рефералка.
- +5 дней за первый вход приглашённого; +15 дней обоим после первой покупки.
- iOS/Android/Windows, Telegram mobile/desktop и обычный браузер.
- Все 8 подключений, мобильный интернет разных операторов, Wi-Fi и LTE-обход.
- Превышение устройств, 500 ГБ общего лимита и списание LTE с коэффициентом ×10.
- Падение x-ui, повреждение тестовой БД, восстановление и отсутствие потери ключей.
- Сообщение в поддержку, ответ администратора и уведомление пользователю.

## 8. Регулярная работа владельца

- Ежедневно: алерты, неоплаченные заказы, обращения, состояние узлов.
- Еженедельно: выручка/конверсия/отток, скорости по операторам, резервные копии.
- Ежемесячно: тест восстановления, доступы сотрудников, сертификаты и расходы.
